Property-scoped grants record the intended host, but property ownership cannot yet be verified; the directory excludes property-scoped grants and overrides until it can. Do not wire it into the API until the property ownership contract, effective grant rules and the identity lifecycle are implemented and verified. The new account table is a minimal access record and is not an account provisioning or login implementation.

Legacy override clearing permits a team manager to remove a DENY without holding the underlying permission. A separate Mungini safeguard requires that permission at the host scope before clearing a DENY, because the removal can restore access. This intentional difference must be reviewed alongside parity.

The identity contact directory is wired to the notification task. Email deliveries with missing identity contacts remain pending and retry hourly without exhausting delivery attempts. Existing users still need contact migration. The lookup excludes suspended users; its database test is written but not run.

Session services require an already authenticated `CurrentUser` and an explicitly assigned active account role. They are not routed, and cannot create an initial login session until verified authentication exists. Refresh tokens are stored as hashes, rotate with the legacy 30-second grace, and use the configured refresh signing secret. Logout-all also advances the access-token revocation cutoff. Account role and session data must be mapped during cutover. Token and database tests are written but not run.

Password authentication foundation: `identity/password_login.rs` verifies the legacy Argon2 and bcrypt formats, uses the legacy five-failure/fifteen-minute account lock, serializes attempts with an account row lock, and creates hashed refresh sessions in the same transaction as successful login. Unknown, ambiguous, disabled and unprovisioned accounts fail closed. The Goma and Kinshasa demo host passwords are `MunginiDemo2026!`, for development seeds only. Password verification tests are written, not run. OTP, account provisioning, password migration, endpoint wiring, login throttling by network identifier, and authorization integration remain open.

Registration verification: `identity/registration_otp.rs` issues email or WhatsApp codes through the real notifications transports, stores keyed HMAC digests with a 15-minute lifetime, limits attempts and returns a one-use 30-minute proof for transactional consumption. Migration `00028` adds persistence; `identity/07-registration-otp.sql` covers pending, locked, expired and verified states with the default development signing key and demo code `123456`. This remains unwired: account provisioning, migration of existing account contacts, network-level rate limiting, provider configuration, expiry job registration and endpoint integration are open. No provider call, database migration or test was run.
